## 事项二 · 延期单重放多市场化（补防线）

**为什么必须做**：延期单是 **2026-09-01 事故复盘**后建的防线
（行情断开时减仓决策被拒且无人重试，白浪费一个交易时段）。**目前只护住 A 股**：

| | A股 | HK | US |
|---|---|---|---|
| 落盘延期（`defer_on_exc`） | ✅ | ❌ | ❌ |
| 重放（`replay_deferred.py`） | ✅ | ❌ | ❌ |

协议层已提供纯操作（`save_deferred`/`clear_deferred`），缺的是**重放路径**。

**难点：重放规则大部分是 A 股特有的**，不能照搬：

| 规则 | A股 | 港股 | 美股 |
|---|---|---|---|
| T+1 可卖量复核 | ✅ 必须 | ❌ 无 T+1 | ❌ 无 T+1 |
| 手数 | 100（科创 200） | **每票不同** | 1 股 |
| 涨跌停 | ±10/20/30% | 无 | 无 |
| 盘后固定价格 | 科创/创业 15:05-15:30 | 无 | 无 |
| 交易时段 | 09:30-11:30 / 13:00-15:00 | 09:30-12:00 / 13:00-16:00 | 美东 09:30-16:00 |
| 券商 | TdxBridgeBroker | Tiger | IBKR |

**设计：把重放循环抽成"市场适配器"**

```
replay_deferred.py（共享循环：过期作废 / 总闸 / 行情新鲜度 / 在途闸门 / 重试）
        │
        ├── 适配器 A股：live_ledger + TdxBridge + T+1复核 + 涨跌停 + 盘后定价
        ├── 适配器 港股：hk_ledger + Tiger + 港交所手数表 + 港股时段
        └── 适配器 美股：us_ledger + IBKR + 1股 + 美股时段
```

共享循环里**已有且与市场无关**的：`MAX_DEFER_HOURS` 过期作废（含上一轮加的
`deferred_expired.jsonl` 留痕）、自动执行总开关、行情新鲜度硬闸、
**在途单闸门**（同代码已有未确认卖单则保留延期）、失败重试与 `defer_on_exc`。

**顺序**：先 A 股（行为保持，有既有逻辑兜底）→ 再 HK/US（**暂停中，可用存根测试**）。

**验收**：HK/US 各有一条"桥断链 → 落延期 → 恢复 → 重放成功"的存根测试；
A 股既有重放逻辑行为不变。

## 事项三 · 行为归因（可算的那两类）

**背景**：影子账户的模式抽取（聚类+决策树）**样本还不够**（当前 0 个已平仓回合），
但归因里的两类**今天就有数据**：

| 类 | 数据来源 | 现状 |
|---|---|---|
| **错过信号** | `live_fills.record_event` 事件台账（哨兵触发但未执行会记，如 `watch_pct_zero`） + `live_price_watch` 的条件位状态 | 有事件，**但没算过代价** |
| **过度交易** | 成交流水（同日同标的反复进出） | 有流水，**没算过** |

**产出**：`scripts/behavior_attribution.py`（离线、可重跑、幂等，与 `roundtrip_features.py` 同套路）：

```
读 成交流水 + 事件台账 + 回合台账
  → 每类缺陷折算成带符号的金额
  → logs/behavior_attribution.jsonl（按 (类别, agent, 日期) 聚合）
```

**"错过信号"的代价怎么算（口径要写死并测试）**：
以条件位触发日**收盘价**为基准，与该规则的触发价差 × 未执行数量。
**不用盘中价**——避免引入不可复现的时点。

**明确不做**：不评"决策对不对"（那是 `decision_track` 的职责），
只算**"该做的动作没做成 / 不该做的动作做了"**的账面代价。

**验收**：
1. 给定造数据（一笔触发未执行的止损 + 一笔同日反复进出），输出金额可手算核对
2. 幂等：重跑逐字节一致
3. **不触碰实盘路径**（纯离线读盘）

## 顺序（三者的依赖关系）

```
事项一（A股切协议）      ← 独立，先做：让协议层覆盖 3/3，之后的改动都有单一真相源
        │
事项二（重放多市场）      ← 依赖事项一（HK/US 要用协议层的 deferred 操作）
        │
事项三（行为归因）        ← 独立，纯离线；但"错过信号"最好在事项二之后做
                            —— 否则会把"延期单还没重放"误算成"永远错过"
```

**⚠️ 事项三必须等在事项二之后**：重放机制没补齐前，HK/US 的"未执行"里
混着"只是还没重放"，归因会**把可恢复的算成永久损失**——那是个会误导人的数字。

## 维护性

| 措施 | 理由 |
|---|---|
| 三件事都先加测试再改 | 台账/重放是实盘路径，golden + 存根测试是唯一的安全网 |
| 重放规则按"适配器"分市场 | 新增市场只写适配器，不改循环——对齐协议层同一思路 |
| 归因口径写死并测试 | 金额类结论最怕口径漂移（本项目已三次栽在"同一规则多份实现"） |
| 归因与 `roundtrip_features` 同套路 | 离线/幂等/占位不跳过，一套模式两处复用 |
