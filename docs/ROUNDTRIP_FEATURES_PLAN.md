# 回合台账 · 价格类特征附件（生产方案）

> 前置：`logs/live_roundtrips.jsonl`（回合台账）已落地——由 `live_ledger.record_sell`
> 产出、`save_ledger` 统一写盘，字段见 `tests/test_live_roundtrips.py`。

---

## 0 · 一个被推翻的判断（先记下来，避免后人重走）

**初判（错）**：价格类特征"必须在买入当时记录，事后补不了（未来函数）"。

**实际**：`entry_rsi14` / `prior_5d_return` 都是**点位时间（point-in-time）可重算**的——
只要有覆盖买入日的日线序列，按"只用买入日之前的数据"切片即可还原。
HKUDS/Vibe-Trading 的 extractor 原话就是 **read as-of the buy date**，
即**抽取时算**，而非买入时记。

**为什么这个纠正很重要**：若按初判去做，会往**实盘买入路径**加一个"算特征 + 写盘"
的步骤——那是在交易链路上新增数据依赖与失败面，**换来的却是本来就不需要的东西**。

> 一般化：**"该在什么时点记录"这个判断，先验证可否重算，再决定要不要动实盘路径。**

## 1 · 数据源核查：**初判为"缺口"，实为误报**（保留下证据链）

**初判（错）**：`stock_daily_latest` / `stock_daily_new_2026_09` 最新只到 2026-09-08，
而你 09-11 有成交 → 判定"日线数据源缺 09-09/10/11，回溯无从做起"。

**追查后的实际情况**：

| 环节 | 事实 |
|---|---|
| celery beat `dispatch_market_sync` | 每分钟派发，多数返回 `dispatched: []` |
| 实际同步任务 `run_market_scheduled_sync` | **正常执行并成功**：09-12 A 股用时 1068s，`parquet.synced=16, total_downloaded=2608` |
| 同步结果里的 `pg_fill` | **`None` —— 但这是设计如此**。任务 docstring 明写：<br>"A 股：QuantDB SDK → parquet → Qlib 缓存（**单源，PG 填充可跳过**）" |

**结论**：`stock_daily_latest` 是**不在 A 股主路径上的遗留表**。A 股的权威数据在
**parquet + Qlib**（`provider_uri: /data/qlib/cn_data`，同步日志报 `status: ok`）。
**管道是健康的，没有缺口。**

**顺带撤回另一处推断**：早前看到该表停在 09-08 时，我曾推测个股终端的"智能标签
对不上"源于数据落后——**这个归因不成立**。标签走的是 DuckDB 视图
（`qdb_technical_indicators` / `qdb_valuation` / `qdb_l1_factors`），读的是 parquet，
与 `stock_daily_latest` 不是同一条路径。

> **两次判断都栽在同一个方法错误上**：拿一张**表**的新旧去推断**整条链路**的状态。
> 正确做法是先确认"这张表在当前架构里还吃不吃饭"，再谈它新不新。
> 这与 §0 的教训同源——**先验证前提，再下结论**。

### 1.1 对本方案的影响

数据源**没有缺口**，所以：

- 特征回溯**可以现在就做**，数据取自 parquet/Qlib（离线、可重跑），不依赖桥在线
- §2.5 的"数据源与降级"保持不变：**优先离线数据源；覆盖不到就标 `insufficient_data`，
  不静默降级到桥**——这条纪律与本次误报无关，它防的是另一种病（缺数被掩盖）

## 2 · 方案：离线特征附件（可重跑、幂等、不含未来信息）

### 2.1 职责边界

```
logs/live_roundtrips.jsonl        ← 回合事实（已落地，纯账本产物）
        │
        ▼  scripts/roundtrip_features.py   ← 本次要做的：离线、可重跑、幂等
logs/roundtrip_features.jsonl     ← 特征附件（按 roundtrip 键关联，不原地改事实）
        │
        ▼  影子账户抽取（后续阶段）
```

**为什么用"附件文件"而不是往回合里写字段**：
- **事实与派生分离**：回合台账是账本产物（`save_ledger` 写），特征是派生数据。
  混在一起会让"账本写入"多一个可能失败的环节。
- **可重算**：特征算法改了（RSI 周期、窗口定义）可以整批重跑，不污染事实。
- **幂等天然**：按 roundtrip 的自然键去重，重跑覆盖同一条。

### 2.2 自然键

回合台账的每行没有 id，用**业务自然键**做关联：

```
(agent, code, buy_ts, sell_ts, volume)   →  sha1 前 16 位作为 feature_id
```

**为什么不用行号**：文件是追加写的，行号不稳定；自然键在重算时仍能对上。

### 2.3 点位时间纪律（**最关键的一条**）

买入发生在 **09:35 盘中**。那一刻 agent 能看到的日线信息上限是 **买入日的前一交易日收盘**。
所以：

| 特征 | 定义（严格无未来信息） |
|---|---|
| `entry_rsi14` | 用 **trade_date ≤ 买入日前一交易日** 的收盘序列算 RSI(14) |
| `prior_5d_return` | `close[前一交易日] / close[前六交易日] - 1` |

**买入当日的收盘价一律不得进入特征。** 这条要写成代码里的显式切片 + 单测，
因为一旦侵入，整个抽取结论都会失真而且**极难事后发现**。

> 边界情形：若买入发生在收盘后/次日开盘前，仍按"前一交易日"取——宁可保守，
> 不做"当日是否已收盘"的分支判断（分支越多越容易在未来某次改动中漏掉）。

### 2.4 幂等与容错

| 情形 | 处理 |
|---|---|
| 该回合已有特征且**输入未变**（同一 `feature_id` + 同一 `data_asof`） | 跳过，不重写 |
| 该回合已有特征但数据源变了 | 覆盖写（最新一次为准） |
| 取不到足够日线（新股/停牌/数据缺口） | **写一条 `status: "insufficient_data"` 的占位**，不静默跳过——否则"缺特征"和"没跑过"分不开 |
| 桥不可用 | 整轮退出并**非零返回**，下次重跑（不做部分成功） |

**"占位而不是跳过"是本方案的核心容错取向**：与 §0 的教训同源——
**静默跳过会让"没算"伪装成"没有这个回合"**。

### 2.5 数据源与降级

```
优先 quantdb 分区表（离线、快、可重跑）
  └─ 覆盖不到买入日 → 该回合标记 insufficient_data，并计入汇总
     （不自动降级到桥：那会让"数据源不全"这个事实被掩盖）
```

**明确不做桥降级**：一旦静默走桥，quantdb 缺数就永远不会被发现——
那正是本仓库反复踩的"假活"型故障。

## 3 · 验收

1. 给定一条已知回合（如 09-11 买入的 603213.SH），能算出 `entry_rsi14` / `prior_5d_return`
2. **点位时间单测**：构造一根"买入日暴涨"的 K 线，断言 `entry_rsi14` **不受其影响**
   （这是防未来信息侵入的回归测试，必须有）
3. 重跑同一批回合 → 输出逐字节一致（幂等）
4. 数据不足的回合 → 出现 `insufficient_data` 占位，不是消失
5. 不触碰任何 `scripts/live_*.py`（**实盘路径零改动**，本方案纯离线）

---

## 4 · 维护性（用户明确要求）

| 措施 | 理由 |
|---|---|
| **特征定义集中在一处** | 三种口径（RSI/前5日/未来的扩展）都在一个 `FEATURES` 表里声明，抽取侧只读它——避免今天刚踩过的"同一公式三个文件各写一遍" |
| **特征名常量与抽取侧共用** | 对齐 Vibe-Trading 的 `PRICE_FEATURES`：名字定义在数据契约边界，防止两侧漂移 |
| **新增特征只需加一个纯函数 + 注册** | 不改调用方、不改落盘格式 |
| **`data_asof` 写进每条记录** | 将来数据被回填/修正时，能判断哪些回合需要重算 |
| **占位而非跳过** | 见 §2.4 |

---

## 5 · 不在本方案内（单独排期）

- **QIFI 式账户协议抽取**：要一次动三条交易路径（`live_ledger` / `hk_ledger` / `us_ledger`），
  属重构，按你的意思单独排。
- **影子账户的模式抽取（聚类+决策树）**：样本量不够（当前 **0 个已平仓回合**），
  等回合台账积累后再做。届时本方案的 `roundtrip_features.jsonl` 就是它的直接输入。
- **行为归因（噪音/漏做/早离/过度）**：纯算术，等回合样本起来即可做；
  其中"错过信号"一类今天就能算（你的条件位哨兵已知"触发未执行"）。
